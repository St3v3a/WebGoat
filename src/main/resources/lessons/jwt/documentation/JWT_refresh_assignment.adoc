== Refreshing a token

It is important to implement a good strategy for refreshing an access token. This assignment is based on a vulnerability
found in a private bug bounty program on Bugcrowd, you can read the full write up https://emtunc.org/blog/11/2017/jwt-refresh-token-manipulation/[here, window="_blank"]

=== Assignment

The hardened event build requires a signed access token and binds each refresh token to its original user. The account-switching attack below describes the original vulnerable flow.

The original exercise used this link:images/logs.txt[logfile] to try to order books as *Tom*. In this build, a token from that log cannot renew with another user's refresh token.
